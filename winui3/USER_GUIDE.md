## 1. 先搞清楚两个概念

### 本地执行

任务跑在**雪乃酱自己所在的这个 Windows 账户**里 —— 用的是本机 `ScriptRunner`，
和以前一样，不需要任何 RDP 环境。任务列表里没选通道的任务就走这条路。

### 会话通道

一条**会话通道**代表"另一套执行环境"：

```text
会话通道 = 目标主机 + 目标账户 + 该账户的凭据 + 一条专用的指令桥目录 + 一个画面连接
```

任务下发给通道后，会在**目标账户**里被一个常驻的「会话代理」执行，
进度和事件实时回传到雪乃酱这边，画面也直接内嵌在雪乃酱窗口里。

### 并行规则（一句话）

> **通道之间并行，通道内部串行。**

- 三条通道可以同时跑各自的任务队列；
- 同一条通道里的任务，仍按「任务执行」页的排序一条条跑；
- 本地执行的那一组，也是单独一条线，和通道任务同时进行。

一次执行最多并行 **8 条通道**，超出的会被截断（并明确告诉你哪几条没跑）。

## 2. 五分钟快速上手

假设你要把「另一个本机账户」跑起来：

| 步骤 | 在哪里 | 做什么 |
|---|---|---|
| 1 | 左侧「会话通道」 | 打开总开关「在目标账户会话中执行任务」 |
| 2 | 同上，通道列表 | 点「新建通道」 |
| 3 | 通道编辑卡 | 填通道名称、目标主机 `127.0.0.1`、目标账户 |
| 4 | 通道编辑卡 | 在密码框里填该账户的密码 → 点「保存凭据」 |
| 5 | 预检区 | 点「开启远程桌面」（若尚未开启；需要管理员） |
| 6 | 预检区 | 点「部署会话代理」（一次性；需要管理员） |
| 7 | 预检区 | 点「重新预检」，确认没有阻塞项 |
| 8 | 左侧「任务执行」 | 选中任务 → 「基础设置」→「执行通道」选刚建的通道 |
| 9 | 顶栏 | 点「开始执行」 |

执行期间左侧菜单会多出「执行中的通道」分组，点进去就能看到画面。

> 目标账户**至少要登录过一次**（切换过去登录一下再回来），代理才会被启动项拉起来。
> 只有代理被拉起并开始写心跳，预检里才会显示「在线」。

## 3. 界面地图

### 左侧菜单

```text
总览                    主页，含「会话通道」概览卡
任务执行                任务列表 + 详情表单（含「执行通道」下拉）
耗时统计
运行日志
会话通道                ← 通道管理与预检页（配置都在这里）
  ├─ 执行中的通道        ← 执行时动态出现，下面按通道列出
  │   ├─ 1 号机 · Player2   ← 点进去是该通道的画面页
  │   └─ 2 号机 · Guest
设置
```

「执行中的通道」这个分组只在**跑过任务之后**出现，停止执行后条目保留（显示已结束状态）。

### 会话通道页（管理页）

从上到下四块：

| 区块 | 内容 |
|---|---|
| 总开关 | 「在目标账户会话中执行任务」；关掉它 = 全部任务本地执行 |
| 通道列表 | 全部通道；右侧「新建通道 / 复制 / 删除 / 重新预检」 |
| 通道设置（编辑卡） | 选中那条通道的全部字段 + 保存 / 清除凭据 |
| 通道预检 | 该通道的环境检查结果、代理状态、部署与开启远程桌面按钮 |

### 通道画面页（`ch:<id>`）

| 区块 | 内容 |
|---|---|
| 通道头 | 通道名、目标（主机 · 账户）、桥目录 + 「单画面 / 多画面 / 连接本通道 / 打开桥目录」 |
| 进度条 | 该通道自己的当前任务、n/N、已耗时、状态与心跳 |
| 画面区 | 单画面一格 / 多画面 2×2 网格 |
| 通道事件 | 该通道自己的事件列表（可「收起」把画面让大一点） |

### 主页概览卡

跑过任务后，主页出现「会话通道」卡：一行一条通道（状态符号 / 名称 / 目标 / 进度 / 状态 / 心跳），
每秒刷新一次，点一行直接跳到该通道画面页。

## 4. 配置一条会话通道

在「会话通道」页选中一条通道，编辑卡里逐项填。

### 字段说明

| 字段 | 说明 |
|---|---|
| **通道名称** | 左侧菜单与各处的显示名。留空会按账户名自动起一个 |
| **目标主机** | 本机另一个账户填 `127.0.0.1`；另一台机器填 IP / 主机名，可带端口如 `192.168.1.20:3390`；填 `rdp://xxx` 会自动去掉前缀 |
| **目标账户** | 该机器上的账户名。**一条通道一个账户，别让两条通道共用一个账户**（它们抢同一个会话） |
| **指令桥目录** | 本机多账户**留空**（自动按账户名分目录）；目标是别的机器时填双方都能读写的共享路径 |
| **密码框** | 只用于点「保存凭据」，存进 Windows 凭据管理器，**不写进 config.json** |
| **远程桌面窗口尺寸** | 「自动」= 内嵌跟随画面格子大小；选固定档位则按该尺寸连接 |
| **该通道任务全部结束后的会话处理** | `保持 / 断开 / 注销`，按通道各配各的 |
| **启用该通道** | 关掉后该通道的任务不会下发（本轮跳过并给出原因） |

### 保存时机

- **文本框**（名称 / 主机 / 账户 / 桥目录）：**焦点离开输入框就自动落盘**，不会因为切页丢填；
- **下拉 / 开关**（分辨率 / 收尾方式 / 启用）：改动即落盘；
- 「保存通道设置」按钮：兜底确认用，不点也不会丢。

### 凭据

- 密码框里填好密码 → 点「保存凭据」。同一台主机上的**不同账户各存一条**，互不覆盖。
- 「清除已保存凭据」按钮按「主机 + 账户」删除，不影响同主机的其它账户。
- 如果系统组策略禁止读写凭据管理器，日志会提示"写入后无法读回"，此时只能手动输入密码。

### 收尾方式怎么选

| 选项 | 效果 | 什么时候用 |
|---|---|---|
| 保持 | 会话放着不管，下次还能直接复用 | 一整天要跑好几轮 |
| 断开 | 断开画面连接，进程与会话保留 | 想省一点资源，但不想重新登录 |
| 注销 | 会话销毁，里面的代理与脚本一起结束 | 跑完就收工；**注意会连带杀掉正在跑的东西** |

## 5. 部署会话代理

跨会话启动进程，Windows 上只有"从那边动手"这一条路，所以代理是**随目标账户登录自启、然后常驻**的。

### 部署做了什么

```text
1. 把程序复制到公共目录（所有用户都读得到）
   目标：C:\ProgramData\YukinoChan\agent\
2. 在公共启动目录建快捷方式
   C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup\雪乃酱 RDP 会话代理.lnk
   → 目标：C:\ProgramData\YukinoChan\agent\YukinoChan.exe --rdp-agent
3. 目标账户下次登录时，快捷方式拉起代理；代理常驻等待指令
```

**为什么必须复制一份**：主控端程序在自己的用户目录下（`C:\Users\<你的账户>\...`），
这个路径**不给其他账户读权限**，快捷方式会被静默拒绝 —— 表现为"远程桌面连上了，任务就是不执行"。
复制到 `%ProgramData%` 就绕开了这个问题。

### 三个要点

1. **只需部署一次**（除非程序更新，或者你从旧版本升级上来 —— 见第 11 节）。
2. **远程目标要在对方机器上部署**：本机的「部署会话代理」按钮管不到另一台机器。
3. **部署后要注销目标账户再重连**：代理是登录时被拉起的，已在登录状态的会话里不会自动多出一个代理。

### 副本被占用时

代理是常驻进程，会一直持有副本目录里的 DLL，此时覆盖部署会被系统拦住。程序会按三档处理：

| 档 | 情况 | 做法 |
|---|---|---|
| ① | 副本目录没被占用 | 原地覆盖，最干净 |
| ② | 被占用，但旧代理**空闲** | 先送走空闲的旧代理，再原覆盖 |
| ③ | 旧代理**正在跑任务** / 送不走 | 跑任务时**拒绝部署**；送不走则退到备用目录 `agent_b` 并改快捷方式 |

> 如果部署失败并提示"需要管理员权限"，多数时候那是**误报** ——
> 真正的原因通常是文件被占用。日志里会写清楚到底是权限问题还是占用问题。

## 6. 把任务分配给通道

「任务执行」页 → 选中一条任务 → 详情「基础设置」→「**执行通道**」下拉：

| 选项 | 含义 |
|---|---|
| **本地执行（当前会话）** | 默认值。跑在雪乃酱自己所在的账户里 |
| **<通道名>** | 下发给那条通道，在它的目标账户里跑 |

- 下拉里的通道顺序与「会话通道」页的列表一致（列表顺序 = 执行分配顺序）；
- 左侧任务列表每一条都会显示它归哪个通道，不用点开就能看出来；
- **新建任务的默认值就是「本地执行」** —— 避免"忘了选通道，任务悄悄跑远程"。

### 引用了不存在的通道会怎样

如果某个任务的 `channel_id` 指向一个**已被删除 / 已停用 / 没配账户**的通道，
这条任务在该轮**不会执行**，并在日志里写明原因。
它**不会**偷偷改成本地执行 —— 因为那可能把已经在目标机跑着的游戏重复拉起来。

## 7. 执行、监控与停止

### 开始

点顶栏「**开始执行**」。日志会先写一行「本轮启动 N 条会话通道并行执行」，然后：

1. 本地那组直接开始跑；
2. 每条通道依次：连接目标账户 → 等待代理在线 → 下发 `command.json` → 轮询进度；
3. 还没连接的通道会自动连接（内嵌模式不会弹任何窗口）。

### 监控三个地方

| 位置 | 看什么 |
|---|---|
| 左侧「执行中的通道」→ 某通道页 | 画面 + 该通道进度、心跳、事件 |
| 主页「会话通道」概览卡 | 一眼看完各通道状态（1Hz 刷新） |
| 看板娘 / 主页状态卡 | 整轮口径：单通道时就是那条通道；多通道时是「执行中（N 块并行）」、进度求和、耗时取整轮墙钟 |

### 心跳与失联

代理等待指令期间每秒写一次心跳。主控端的判定顺序是：

1. **先看这条状态是不是本轮指令写的** —— 不是就当作"代理还没接到指令"，**不报失联**；
2. 刚下发指令的 30～90 秒是宽限期（登录 + 拉起代理 + 初始化大约要 25 秒），期间不报失联；
3. 过了宽限期才按"多久没更新"判断，并区分是否处于活动状态。

一条通道失联**只影响那一条**，其它通道照常。心跳恢复后会补一条「✓ 会话代理心跳已恢复」的日志。

> 折中：90 秒以内的真断线，最迟要等到宽限期结束（约 90 秒）才会告警。

### 停止

| 操作 | 快捷键 | 行为 |
|---|---|---|
| 停止执行 | `F8` | 停止当前这一轮：本地下发停止请求，同时给**每条通道**各写一份 `stop.json` |
| 紧急停止 | `Ctrl+Alt+F8` | 更强制的一档，同样下发到全部通道 |

代理在执行期间每秒检查一次 `stop.json`，读到就转成脚本引擎的停止请求，随后收尾。
所以按下停止后**有一拍延迟**是正常的。

### 收尾

- 每条通道按它自己配的「会话处理」方式收尾（保持 / 断开 / 注销）；
- 整轮全部结束后，日志出现一行 `[汇总] 共 N 块（本地 X / 通道 Y）：成功 …、异常 …。`，
  下面跟逐块明细（**异常块排在最前面**）；
- 只弹**一条**汇总通知（`rdp.notify_on_all_done`）。单块执行（只有本地，或只有一条通道）不发汇总 ——
  它和按块通知重复；
- 看板娘在**整轮结束**时才从「工作」变「休息」。某条通道先跑完的那一刻它仍在工作态 —— 那是故意的。

## 8. 画面：单画面 / 多画面 / 全屏

通道页顶部的「单画面 / 多画面」是**画面排布方式**，不是连接模式。

### 单画面

只摆本通道一格，占满整个画面区。**保留「全屏」**（画面右上角）：

- 全屏会开一个独立的全屏窗口，并接管键盘 —— `Win`、`Alt+Tab` 等系统组合键会**转投远端**；
- `F11` 或双击画面退出全屏，退出后本地键盘立即恢复；
- 同时只允许一个全屏窗口：从另一条通道再点全屏，前一个会被自动收掉。

### 多画面

2×2 四格并列显示全部活跃通道，每格标通道名与状态：

- 通道多于 4 条时出现「上一页 / 下一页」（**翻页**，不是滚动）；
- 每格可单独「弹出窗口」→ 变成一个普通可缩放窗口，你可以自己并排摆放；
- 关掉弹出窗口后，画面**自动回到**页面里那一格；
- **多画面下不提供全屏**（会盖掉其它几路）；双击某格 = 把它弹成独立窗口。

为什么每页 4 格：8 路画面同时渲染的 CPU / GPU 开销不可接受。分页天然保证"同时渲染不超过 4 路"，
翻页时用不到的格位会被解挂、不参与渲染。

### 操作画面

点击画面获得焦点后，鼠标与键盘直接作用于远端。

| 情况 | 说明 |
|---|---|
| `Ctrl+Alt+Del` | 系统安全序列，**任何客户端都转发不了**；远端任务管理器请用 `Ctrl+Shift+Esc` |
| 画面黑屏 | 程序会自动重试几次；仍黑屏就点「断开」再重连，或把连接方式改回「独立窗口」 |
| 几路画面互相闪烁 | 一个客户端同时只能挂一块画面。先关掉那路的弹出窗口再重开 |
| 画面太小 | 点事件卡的「收起」，画面会多拿一块高度；窗口拉大也有用 |

### 独立窗口模式（`mstsc`）

在通道管理页把「连接方式」改成「独立窗口」，之后连接会用系统自带的远程桌面客户端开窗口。
这是最稳、永远可用的兜底方案，但画面不在雪乃酱里，也**不支持多画面同屏**。

## 9. 几种典型配置

### A. 一台机器 + 两个账户

```text
通道 1：主机 127.0.0.1 / 账户 Player2    桥目录留空
通道 2：主机 127.0.0.1 / 账户 GameBot    桥目录留空
```

能否真正同时跑，取决于你的系统是否允许多个交互式会话并存。
如果不能，第二个连接会把第一个桌面顶掉 —— 这种情况请用方案 B。

### B. 两台机器

```text
通道 1：主机 192.168.1.20 / 账户 Player2   桥目录 \\192.168.1.20\YukinoBridge
通道 2：主机 192.168.1.21 / 账户 Player2   桥目录 \\192.168.1.21\YukinoBridge
```

要点：

- 桥目录两边都要能读写（共享文件夹 / NAS / 同步盘都行）；
- 代理要在**对方机器**上各自部署一次；
- 对方机器上也要装一份雪乃酱（部署按钮就是从当前程序复制的）。

### C. 混合：本地 + 远程

```text
任务 A → 本地执行（当前会话）
任务 B → 通道 1
任务 C → 通道 1
任务 D → 通道 2
```

执行结果：本地一条线、通道 1 一条线（B 跑完才跑 C）、通道 2 一条线，三条线并行。

## 10. 配置文件长什么样

配置在仓库根的 `config.json`（与 Python 版共用同一份）。会话通道相关的部分：

```jsonc
{
  "rdp": {
    "enabled": true,
    "client_mode": "embedded",        // embedded = 内嵌画面；mstsc = 独立窗口
    "audio_enabled": true,
    "gfx_enabled": false,
    "connect_timeout_seconds": 120,
    "notify_on_task_done": true,      // 每个任务完成都发通知
    "notify_on_all_done": true,       // 整轮结束发一条汇总

    "channels": [
      {
        "id": "ch-7f3a",              // 稳定 id，任务的 channel_id 指向它
        "name": "1 号机 · Player2",    // 菜单显示名
        "host": "127.0.0.1",
        "user": "Player2",
        "bridge_path": "",            // 留空 = <ProgramData>\YukinoChan\rdp\<user>
        "credential_saved": true,
        "session_finish": "keep",     // keep / disconnect / logoff
        "desktop_width": 1280,
        "desktop_height": 720,
        "enabled": true
      }
    ]
  },

  "tasks": [
    { "name": "原神", "channel_id": "ch-7f3a", "order": 1 },
    { "name": "星铁", "channel_id": "",        "order": 2 }   // 空 = 本地执行
  ]
}
```

**密码永远不在这个文件里** —— 它只存在 Windows 凭据管理器中，键为 `YukinoChan/RDP/<主机>|<账户>`。

### 命令行参数（排查用）

| 参数 | 用途 |
|---|---|
| `--rdp-agent` | 以会话代理身份启动（部署快捷方式时自动带上；一般不用手敲） |
| `--bridge:<目录>` | 指定桥目录（代理用，远程目标部署时由部署流程写入快捷方式） |
| `--embed-vm <host> <user> <password>` | 自检：走正式 VM 路径自动连接一条内嵌会话，过程全写日志 |

## 11. 升级注意

### 从旧版本升级必做

桥目录规则变了：

```text
旧：<ProgramData>\YukinoChan\rdp\
新：<ProgramData>\YukinoChan\rdp\<账户名>\
```

**必须重新点一次「部署会话代理」**，然后**注销目标账户再重连**。
否则新版主控端在新目录读写、旧代理还在旧目录里转，表现就是「代理明明在跑，却一直显示不在线」。

### 会自动完成的迁移

- 旧配置里没有 `channels` 时，会**自动迁移出一个默认通道**（继承原来的目标账户、桥目录、分辨率、收尾方式），
  并把所有任务指向它 —— 也就是说，升级后**原来能跑的行为不变**，不需要手工重配；
- 旧桥目录里的 `status.json` 如果还在旧位置，程序会给出提示。

### 行为变化

- 内嵌画面改用原生 FreeRDP 实现，旧 COM ActiveX 方案（`YukinoChan.RdpHost`）已删除；
- 旧的「远程会话」菜单项已改名为「会话通道」，原来的单通道配置界面（`RdpPage`）被拆成
  「会话通道（管理）」+「各通道画面页」两个部分；
- 远程执行时顶栏「停止执行」**现在真的可用**（改造前远程模式下它是灰的）。

## 12. 出问题先看这里

| 现象 | 先查什么 |
|---|---|
| 预检说代理未部署 | 点「部署会话代理」（需要管理员）。远程目标要在对方机器上部署 |
| 预检说代理不在线 | 目标账户**登录过**吗？登录过还不行就注销再重连一次（代理是登录时拉起的） |
| 「代理在跑却显示不在线」 | 是不是刚从旧版本升级上来？**重新部署一次代理**（桥目录规则变了） |
| 开始执行后提示"本轮未启动" | 看日志里逐条写的原因：超 8 条上限 / 通道被停用 / 没配账户 / `channel_id` 指向了已删除的通道 |
| 任务完全不执行 | 打开 `%ProgramData%\YukinoChan\rdp\<账户名>\status.json`：`AgentUser` 为空、时间停在"下发那一刻" = 目标会话里的代理没起来 → 重新部署代理 |
| 停止执行没反应 | 停止要等代理下一拍读到 `stop.json`。长时间不停就看该通道心跳时间是否还在走，不走说明代理已不在 |
| 某条通道报失联，别的正常 | 那是**预期行为**：只有那一条通道受影响。先看它目标账户的桌面是否被注销了 |
| 提示需要填「指令桥目录」 | 目标是远程主机时的正常拦截；只想切本机账户的话把主机改回 `127.0.0.1` |
| 画面黑屏 | 点「断开」再重连；仍不行就把连接方式改成「独立窗口」 |
| 画面挤在一条横带里 | 点事件卡的「收起」，或把窗口拉大 |
| 全屏后本地键盘失灵 | 用 `F11` 或双击退出全屏（退出时会先摘键盘钩子，本地立即恢复） |
| 分辨率不是我想要的 | 改档位后要**重新连接一次**；内嵌模式的分辨率跟随画面格子大小 |
| 想彻底重置 | 删掉 `config.json` 里的 `rdp.channels` 节点（配置丢），或删掉整份 `config.json`（全部回默认） |

完整的排障表（含 RDP 层与凭据层的问题）见 [README.md 的「排障」一节](README.md#排障)。
